= CoprocessorRuntime.jl - Project Topology
:toc:

The module and file topology of the package, taken from the `include`, `import`
and `using` statements in `src/CoprocessorRuntime.jl`, `ext/AcceleratorGateExt.jl`
and `test/runtests.jl`. It describes structure only; it carries no completion
percentages, because none has been measured. For status see `status/ROADMAP.adoc`
and `status/READINESS.adoc`.

== Module and include order

`src/CoprocessorRuntime.jl` declares `module CoprocessorRuntime`, exports the
public names, and includes seven files in this order. There are no `using` or
`import` statements in `src/`: the package has no dependencies and the files
share one module namespace.

[source]
----
module CoprocessorRuntime            src/CoprocessorRuntime.jl
  include("Kinds.jl")                Role, CoprocessorKind, kind_label, coprocessor_kind
  include("Grades.jl")               ResourceGrade, tropical_seq/alt, dominates
  include("EchoLoss.jl")             TransferMap, EchoResidue
  include("Sessions.jl")             Session, open_session, close_session!
  include("Receipts.jl")             WarrantKind, LaunchReceipt
  include("Nullity.jl")              CNOClaim, ONDClaim, InverseMeta
  include("Choreography.jl")         Endpoint, LaunchPlan, project, HubCeilingRefusal
end
----

== Which file uses which

An arrow `A --> B` means the code of `A` refers to a type defined in `B`.
Include order respects every arrow.

[source]
----
   Kinds.jl        Grades.jl       EchoLoss.jl       (no dependencies)
     |   \             |               |
     |    \            |               |
     v     \           v               v
 Sessions.jl \         +------+--------+
     |   |    \               |
     |   |     +--------------+---> Choreography.jl
     |   |                         (Role, CoprocessorKind, ResourceGrade, EchoResidue)
     v   v
Receipts.jl   Nullity.jl           (both use Session)
----

[cols="1,2",options="header"]
|===
| File | Refers to

| `Kinds.jl` | nothing
| `Grades.jl` | nothing
| `EchoLoss.jl` | nothing
| `Sessions.jl` | `Kinds.jl` (`CoprocessorKind`, `Role`, `HostRole`)
| `Receipts.jl` | `Sessions.jl` (`Session`, `isopen`)
| `Nullity.jl` | `Sessions.jl` (`Session`, in `reset_session!`); `EchoResidue` is named only in a docstring
| `Choreography.jl` | `Kinds.jl` (`Role`, `CoprocessorKind`), `Grades.jl` (`ResourceGrade`), `EchoLoss.jl` (`EchoResidue`)
|===

== The optional extension

[source]
----
   AcceleratorGate.jl  (weak dependency, [weakdeps] in Project.toml)
          |
          |  both loaded
          v
  ext/AcceleratorGateExt.jl  ---->  CoprocessorRuntime (coprocessor_kind and the *Kind types)
----

`AcceleratorGateExt` imports `coprocessor_kind` and the eight kind types from
`CoprocessorRuntime`, and sixteen names from `AcceleratorGate` (`AbstractBackend`
and fifteen backend types). Julia loads it only when both packages are loaded.
Nothing in `src/` refers to it, so the core stays free of the dependency.
