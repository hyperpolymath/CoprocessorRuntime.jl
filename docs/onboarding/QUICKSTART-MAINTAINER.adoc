:toc:
:toclevels: 2

== Overview

CoprocessorRuntime.jl is a Julia library distributed as source from its Git
repository. There is nothing to package or deploy: no binary, no installer, no
container image, and no Guix or OPSM package. Users install it with
`Pkg.add(url=...)`.

It is not in the Julia General registry and will not be released there, so
there is no registry release step and no version to register.

== Dependencies

* Runtime: none. The `[deps]` table in `Project.toml` is empty.
* Optional: `AcceleratorGate` is a weak dependency (compat `0.1`) behind the
  package extension `AcceleratorGateExt`. AcceleratorGate is not in General
  either, so `test/ext/Project.toml` fetches it by URL from a pinned commit
  (`rev`). Moving that pin is a deliberate change: re-run the extension tests
  on Julia 1.11 when you do.
* Test: `Test` and `Aqua`, declared under `[extras]`.
* Julia: `julia = "1.10"` is the floor. CI's oldest leg is 1.10, so raising or
  lowering the floor means changing `[compat]` and the CI matrix together.

== What CI gates

`.github/workflows/julia-ci.yml` runs on pull requests and on pushes to `main`
and `master`:

[cols="1,3"]
|===
| Job | What it checks

| Format (JuliaFormatter)
| `src/`, `test/` and `test/cases/` are formatted. Check mode only; CI never writes.

| Static analysis (JET)
| `JET.test_package(CoprocessorRuntime)`.

| Test (Test + Aqua)
| `Pkg.test()` on Julia 1.10 and the latest 1.x. The extension tests run only
  on 1.11 or later and are reported as `Broken` on 1.10.
|===

The exact commands are in the
link:QUICKSTART-DEV.adoc#_checks_ci_runs[developer quick start]. Other workflows
in `.github/workflows/` are template-wide estate checks.

== Merging

* Every commit must be signed. A ruleset (`.github/rulesets/base.json`)
  requires signatures. See link:../../CONTRIBUTING.adoc[CONTRIBUTING] for how.
* Pull requests are squash-merged; that ruleset allows no other method.
* The ruleset's `required_status_checks` list is currently empty, so no
  check is enforced by GitHub as required. Do not merge over a red Julia CI
  run regardless.
* After a squash-merge, delete the feature branch and start follow-up work from
  the current `main`.

== Releases

There is no registry release. The repository has a generic `release.yml` that
fires on `v*` tags; it comes from the template and this guide does not cover
it. Record user-visible changes under `[Unreleased]` in `CHANGELOG.adoc`.
