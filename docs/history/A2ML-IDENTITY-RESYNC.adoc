= Identity moved from A2ML to the repo deed, 2026-11-17

This repository was minted from `rsr-template-repo` but kept the template's own
identity: the deed header named `rsr-template-repo`, and `CLADE.a2ml` and
`ECOSYSTEM.a2ml` described the template. The identity now lives in
`CoprocessorRuntime.jl_chora.deed` and the `CLAUDE.md` arrival pack is
generated from it. A2ML is retired estate-wide; no `.a2ml` file was created,
restored or edited, and none was converted. This record follows the shape of
boj-server's `docs/history/A2ML-REMOVED.adoc`.

== Removed

No `.a2ml` file was removed. The two files that held the template's identity
are kept, because live readers remain (next section).

== Kept because a live reader still needs them

Both files still describe `rsr-template-repo`, not this repository. Nothing
reads them for identity any more: the arrival pack (`extract.sh`) reads the
deed. They stay until the readers below are moved.

The other `.a2ml` files (`STATE`, `AGENTIC`, `META`, `NEUROSYM`, `PLAYBOOK`,
`anchors/ANCHOR`, the contractile Xfiles, the integrations, the policies and
`rsr-profile`) were not touched. This change does not retire them.

== Why the coaptation readers were not moved

The template's current coaptation reads the deed, but its `extract-clauses.sh`
also reads each contractile's `declaration` field from `<verb>/<verb>.k9.ncl`.
This repository's six contractile K9 files are an older generation: each keeps
its declaration in the matching `.a2ml` Xfile and imports
`../k9/template-hunt.k9.ncl`, which does not exist in the tree, so the current
extractor fails here (run on 2026-11-17 with nickel 1.9.1). Moving the contractiles forward is a separate change from identity.
Until then `CLADE.a2ml` and `ECOSYSTEM.a2ml` stay. The committed coaptation
receipt was already stale before this change (`verify.sh` reported drift on
`main`); this change does not touch it.

To delete the two files: move the coaptation to the deed together with the
contractile K9 files, replace the existence checks named above, then delete
them and add them to a removal ledger.

== Where the identity went

* `CoprocessorRuntime.jl_chora.deed`: header `:canonical-name`, `:repo-uuid` and
  `:beholding-chora`; `(identity)`, `(forges)`, `(lineage)`, `(status)`,
  `(maturity)`, `(ecosystem)` with its `(related …)` entries, a minimal
  `(anchor)` with the golden path, and `(ply)` brought to the template's text.
* `CLAUDE.md` "This repo" block: generated by `just claude-md` from the deed.
* The clade is left unassigned. chora-registry is authoritative for it, and
  registering is the owner's act.
