= AI-Assisted Installation Guide
:toc:
:toclevels: 3
:sectnums:

This guide is for an *AI agent* installing, using or verifying the Julia
package `CoprocessorRuntime.jl`. A human following it will not be misled; the
ordering and the warnings are written for an agent working non-interactively.

[[ai-implementation]]
== Implementation for an AI agent

=== 1. Orient before acting

Read, in this order, before running anything:

. `*_chora.deed` (the repo deed) at the repository root.
. `CLAUDE.md` -- the generated arrival pack (estate doctrine and repo identity).
. `README.adoc` -- what the package is and is not.

Do not infer the package's capabilities from its name. It is a host-side
contract and evidence layer: it records launch semantics and does not run
accelerator kernels, select a backend, or prove CNO/OND. If a fact is not
written down, report it as unknown rather than inventing it.

=== 2. Install the package as a dependency

The package is not in the Julia General registry. Install it by URL:

[source,julia]
----
using Pkg
Pkg.add(url="https://github.com/hyperpolymath/CoprocessorRuntime.jl")
----

It needs Julia 1.10 or later and has no dependencies of its own.
`AcceleratorGate.jl` is an optional weak dependency, also not in General; add it
by URL only if the `coprocessor_kind` mapping is wanted.

=== 3. Or work on a checkout

When no revision is requested, take the repository from `origin/main`, never
from a stale local working tree. When a pull request or branch is named, check
out and test that revision instead.

[source,bash]
----
git clone https://github.com/hyperpolymath/CoprocessorRuntime.jl.git
cd CoprocessorRuntime.jl
julia --project=. -e 'using Pkg; Pkg.test()'
----

`Pkg.test()` runs Aqua and the case files in `test/cases`. On Julia 1.11 it
also runs `test/ext` in a subprocess, which fetches `AcceleratorGate` from
GitHub; on Julia 1.10 that step is recorded as one `Broken` test. Set
`COPROCESSORRUNTIME_SKIP_EXT_TESTS=1` to skip it (it is then also recorded as
one `Broken` test, not dropped).

[WARNING]
====
Running the tests on Julia 1.11 writes `test/ext/Manifest.toml`, and
`--project=.` use writes a root `Manifest.toml`. Both are listed in
`.gitignore`; do not force-add them. Use a scratch copy and a scratch
`JULIA_DEPOT_PATH` if the working tree must stay clean.
====

=== 4. Verify the result

[source,julia]
----
using CoprocessorRuntime
s = open_session(GPUKind())
r = issue_receipt(s; warrant = WarrantOnly, claim = "planned")
@assert !host_may_claim(r)
close_session!(s)
----

A correct install loads without error and the assertion passes. See
`QUICKSTART.adoc` for a longer first run and its expected output.

=== 5. What not to claim

* Do not report a CNO or OND claim as proved. Status is `:unproved` or
  `:model_checked`.
* Do not report a receipt as host knowledge unless `host_may_claim` is true.
* Do not treat `Idris`, `Zig` or other files under `src/interface/` as the
  Julia API; that seam is not wired to this package (`src/README.adoc`).

== Privacy

The package performs no telemetry and makes no network requests: `src/` and
`ext/` contain no network or file I/O.

What does touch the network is installation and testing, not the package:

* `Pkg.add(url=...)` and `git clone` fetch from GitHub.
* `Pkg.test()` on any supported Julia needs the Aqua test dependency
  (`[extras]` and `[targets]` in `Project.toml`). With an empty depot, even on
  Julia 1.10, where the extension tests are skipped, it can download Aqua and
  the General registry data needed to resolve it.
* `Pkg.test()` on Julia 1.11 also fetches `AcceleratorGate.jl` from GitHub at
  the commit pinned in `test/ext/Project.toml`, and may update the Julia General
  registry.

Do not invent identity values (owner, author, email) when editing files; report
a gap instead.
